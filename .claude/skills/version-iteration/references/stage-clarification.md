# Stage: Clarification

## 目标

把用户意图收敛成可执行、可验证、边界清楚的任务定义。

## 进入条件

- 用户目标模糊或只给方向；
- 范围、非目标、验收标准、数据边界、交互行为或风险接受条件不完整；
- 当前请求可能改变 MVP 目标、业务规则、交易风险、凭据/数据处理或发布边界。

## 必做规范

- 区分可自行查证的事实、工作假设和必须由用户决定的事项。
- 可查证的先查证，不把本地可验证事实抛给用户。
- 只问会改变目标、范围、验收、业务规则、数据、发布或风险承担的问题。
- 对 InvestPilot 默认收敛到一个小切片：本地 TUI、AI 聊天、研究辅助、可运行验证。
- 明确非目标，尤其是 RAG/KG/数据流水线/交易执行等未来能力。

## 输出标准

Clarification 通过时必须得到：

- 用户可见目标；
- in scope / out of scope；
- 可观察 acceptance criteria；
- 关键约束和风险；
- 下一 Stage 建议。

## Gate 标准

PASS 需要有用户消息、仓库文档或代码事实作为证据。Clarification 的任务定义、结论和证据包必须由不同实例的独立 verifier 对最新版本给出 PASS，才能进入下游 Stage；仍需用户决策时必须 BLOCK / Escalate，不得进入 Design 或 Execute。
