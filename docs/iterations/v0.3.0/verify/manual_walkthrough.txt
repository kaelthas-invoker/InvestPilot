Notes / Concerns
-------------------------------------------------------------
1. _seed_for_test is referenced in the task brief but is NOT defined anywhere
   in src/investpilot/storage/. The probe script seeds manually using
   repo.create_session + repo.append_message, which is the same code path the
   TUI uses. Not a blocker, but worth confirming the brief was referring to a
   removed/never-shipped helper.

2. ChatSession.send uses bare `return; yield` after the empty-text guard —
   `return` returns from the generator so `yield` is unreachable, but this is
   only meaningful for callers that introspect the function. Verified the
   empty-text path doesn't actually produce anything during the walkthrough
   because we always send non-empty text.

3. Persistence writes (session row + user row + assistant streaming row +
   final update) all completed cleanly with no warnings. FOREIGN KEY pragma
   is ON in open_db but the dump file shows PRAGMA foreign_keys=OFF at the
   top — that's just .dump's default, not a real-world behavior change.

4. The two-step seed (system row not stored at create_session time, only at
   first append_message) means a session row with message_count=0 will NOT
   appear in list_sessions. SPEC §9 filter `WHERE s.message_count > 0`
   enforces this — confirmed by list_sessions count = 1 after seeding a
   session that only had create_session called.
